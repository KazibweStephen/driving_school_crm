## Session Summary — Expense Categories: Mandatory + No-Wipe + Auto-Fill + Duplicate Guard (Uncommitted, backend restarted + frontend rebuilt)
- **User request (4 parts)**: (1) "The Category should be mandatory"; (2) "The Category still fails to display on the Expenses list, it used to display but something may have broke"; (3) "selecting the package, removed the already selected category and selected user, amount is not populated in the Amount input"; (4) "there is not validation for just one expense to be filed per category on the package."
- **Root cause (all 4 complaints traced to one bug)**: web+mobile `onCartItemChange()` unconditionally set `form.category = ''` whenever the cart item had ≠1 *payable* tagged type. Since the dialog field order is **Category → Client → Cart Item**, selecting the package wiped the already-picked category → `needsClient()` became false (`selectedCategory()?.requires_client`) → the Client block vanished (looked like the user was removed) → `save()` sent `category: ''` (empty string, backend stored it) → the list's `e.category || '-'` rendered `-` (the "fails to display" complaint) → the backend duplicate guard `if cart_item_id and category:` was silently skipped because category was falsy (the "no validation" complaint). Amount was only auto-filled for `payable.length === 1`; the permit-context `openCreateForContext()` set `cart_item_id` directly WITHOUT calling `onCartItemChange`, so tagged types + amount never loaded there.
- **Backend fixes** (`services/finance.py`, `api/v1/companies.py`): `create_expense` now 400s "Category is required" for blank category (strips whitespace, stores trimmed); the legacy `/branches/{id}/expenses` endpoint got the same guard. Duplicate guard made **case/space-insensitive** via `func.lower(func.replace(Expense.category,' ','')) == category.lower().replace(' ','')` — e.g. a second " permit   payment " no longer slips past "Permit Payment".
- **Web fixes** (`features/expenses/expenses.ts`): `formIsValid()` now requires a non-empty `form.category` first (before the `__other__`/otherDetail rule). `onCartItemChange()` no longer wipes — it keeps an already-selected category when it matches a payable tagged type (auto-fills amount from `currentMatch.amount`), only auto-selects when no category is chosen AND exactly one payable exists, and never touches the client. `needsClient()` now returns true whenever `form.cart_item_id` is set (tagged flow always implies a consultation/client). `openCreateForContext()` now calls `this.onCartItemChange(this.form.cart_item_id)` so the permit-context dialog loads tagged types + auto-fills the amount.
- **Mobile fixes** (`frontend/mobile/src/app/features/expenses/expenses.ts`): mirrored — `onCartItemChange` no-wipe + auto-fill, `needsClient()` includes `cartItemId()`, `submitExpense()` 400-style warn toast "Select a category" for empty category, `openCreateForContext()` triggers `onCartItemChange`.
- **E2E** (`expenses.spec.ts`): first test now selects a **category** in the dialog (Category is mandatory) — used **Vehicle Maintenance** (petty-cash, no client) NOT "Permit Payment" (client-account, requires client → Create stays disabled), and asserts the category renders in the list. 2/2 pass.

## Multi-Company Architecture
- **Company** (`companies`): Top-level tenant with `id`, `name`, `code` (unique), `address`, `phone`, `email`, `is_active`
- **Branch** (`branches`): Belongs to a Company (`company_id` FK); `name`, `code` (unique), `address`, `phone`, `email`, `is_active`
- **User.company_id**: nullable FK — null for super_admin, set for company-scoped users
- **User.is_company_admin**: boolean flag for company-level admin role
- **UserBranchAssignment**: M2M between users and branches with optional `role` override
- **VehicleBranchAssignment**: M2M between vehicles and branches (car sharing)
- **Expense** (`expenses`): branch-scoped (`branch_id` FK)
- **Sale** (`sales`): branch-scoped (`branch_id` FK)
- **Scoped models** (have `company_id` FK): Product, Vehicle, LessonPlanTemplate, LessonLibrary, VideoLibrary
- **Scoped models** (have `branch_id` FK): Consultation, ClientAvailability
- Default Company (`00000000-0000-0000-0000-000000000001`) and Main Branch (`00000000-0000-0000-0000-000000000002`) are seeded; all existing records backfilled to them
